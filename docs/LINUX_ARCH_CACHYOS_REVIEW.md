# Arch and CachyOS capture compatibility

At revision `6474ee3`, Instant Replay and Recording can start with no readable input event devices, input group membership, Shadowless input rule, or installed input setup helper. Portal capture also has a route with no polkit authentication. **Direct monitor capture can require administrator authorization.** A fresh profile takes the first advertised source, and GSR lists monitors before the portal. Starting replay on login can therefore select KMS. [Settings::capture](../linux/settings/settings.cpp), [GSR source enumeration](../linux/third_party/gpu-screen-recorder/src/cli/commands.c)

## Requirements by capture route

These are host requirements for both distributions. “Required for” identifies the operation that fails when the dependency is missing.

| Dependency | Required for | Behavior and source evidence |
| --- | --- | --- |
| Native Qt Wayland platform and Hyprland or Plasma 6 session | Application | The primary process checks platform `wayland` and a colon-separated desktop identity containing Hyprland, KDE or Plasma. An unsupported session exits. Xwayland itself is optional for GSR. [Desktop gate](../linux/platform/hyprland/desktop_session.h), [main](../linux/app/main.cpp), [GSR windowing](../linux/third_party/gpu-screen-recorder/src/recorder/windowing.c) |
| Private user runtime directory, local sockets, writable temporary space and video destination | Application IPC and both capture modes | A missing runtime location, failed lock or socket prevents startup. Capture needs space for its control sockets, private audio state, staged KMS files and output. Preparation errors or file write failures prevent starting or saving. [main](../linux/app/main.cpp), [GsrCapture::start](../linux/capture/gsr_capture.cpp), [CaptureAudio::start](../linux/capture/audio.cpp) |
| Graphics driver with working EGL and a supported hardware encoder | Both modes | The managed engine must advertise a source and H.264, HEVC or AV1 through `--info`. Unavailable selections fail validation. The app disables CPU encoder fallback. [GSR probe](../linux/third_party/gpu-screen-recorder/src/cli/commands.c), [GsrOptions::validate and arguments](../linux/capture/gsr_capture.cpp) |
| Managed GSR executable, matching composition plugin, KMS server and private helper libraries | Both modes in this distribution | Shadowless resolves its own engine. The controller checks the plugin even with overlays off. The launcher stages the KMS payload before every invocation, including portal and capability queries. A missing payload can invalidate the probe before capture starts. A system GSR installation is optional. [Engine path](../linux/capture/gsr_capture.h), [Controller::toggleCapture](../linux/app/controller.cpp), [launcher](../linux/engine/launch-recorder) |
| Session D-Bus, `xdg-desktop-portal`, desktop ScreenCast backend, approved screen selection and working PipeWire video stream | Portal video | Use the Hyprland or KDE backend for the session. Failure to create the portal session removes that source from the probe. Denying selection or failing PipeWire negotiation prevents the selected capture from starting. KMS has its own source and authorization path. [Portal setup](../linux/third_party/gpu-screen-recorder/src/capture/portal.c), [source probe](../linux/third_party/gpu-screen-recorder/src/cli/commands.c), [Arch Hyprland backend](https://archlinux.org/packages/extra/x86_64/xdg-desktop-portal-hyprland/), [Arch KDE backend](https://archlinux.org/packages/extra/x86_64/xdg-desktop-portal-kde/) |

It executes an already privileged helper directly or calls `pkexec`. The managed build installs no permanent capabilities. Failure to authorize stops this capture attempt. The user can select an advertised portal source. Independently, the optional input grant/revoke UI needs `pkexec` and the input helper. Without a graphical agent its password dialog cannot appear. The input UI handles cancellation and offers manual steps when setup is unavailable. Neither grant is needed for portal video. [KMS client](../linux/third_party/gpu-screen-recorder/kms/client/kms_client.c), [InputAccess outcomes](../linux/overlays/input/access/input_access.cpp), [input panel](../linux/ui/input_overlay_panel.cpp) |
| `pipewire` and `pipewire-pulse` with working session routing (typically WirePlumber) | Default application audio, including with KMS | The default PC track requests application audio. GSR checks the Pulse server is PipeWire and fails startup if application audio setup fails. Device tracks need their selected Pulse-compatible devices. With system audio, application modes and microphone off, the app emits no audio tracks. Portal video still needs PipeWire. The code checks working services and devices, not a session manager by name. Dashboard, tray and running-instance commands can still control capture. Plasma uses the assigned portal bindings. Hyprland additionally installs temporary compositor binds. AppImage enforces the Hyprland tool at launch. [Shortcut registration](../linux/platform/hyprland/shortcuts.cpp), [command dispatch](../linux/app/controller.cpp) |
| Readable selected `/dev/input/event*` nodes | Optional, for live input preview and saved input events | Without read access the overlay reports denied or disconnected. A preview or enabled sidecar supplies the allowlist. The controller starts the source only for a nonempty list. The media save is independent of a sidecar write failure. ## Package boundaries

- **AppImage host tools, required today.** Normal launch checks for `ffmpeg` and `ffprobe` (Arch package `ffmpeg`), `pactl` (`libpulse`) and, on Hyprland only, `hyprctl` (`hyprland`). A missing executable exits before the UI opens. Native editor processes use FFmpeg for analysis/export. Native audio uses pactl for icons and optional microphone following, with direct-device fallback if sink creation fails. FUSE is optional with `--appimage-extract-and-run`. [AppRun](../linux/packaging/AppRun), [media tools](../linux/player/media_tools.cpp), [audio](../linux/capture/audio.cpp), [installation](INSTALL.md)
- **Native build and linked runtime.** The app links Qt 6 (`qt6-base`, `qt6-multimedia`), LayerShellQt (`layer-shell-qt`), libmpv (`mpv`) and FFmpeg. Missing linked libraries prevent loading. The Wayland platform and layer-shell plugins supply the native panel. SVG and WebP support come from `qt6-svg` and `qt6-imageformats` for icons and media. AppImage stages Qt plugins and libraries. On the reviewed CachyOS host `pacman -Qo` identifies `qt6-base` as the provider of both qmake6 and the Wayland platform plugin. [App linkage](../linux/app/ShadowlessLinux.pro), [overlay surface](../linux/platform/hyprland/overlay_surface.cpp), [plugin staging](../linux/packaging/build_appimage.py), [Arch Qt packaging change](https://archlinux.org/todo/qt6-wayland-dependency-cleanup/)
- **Source build tools and engine libraries.** Building requires a C/C++17 toolchain, Make, qmake6/Qt Test, pkg-config, Python, Meson, Ninja, patchelf, OpenGL and Vulkan headers. The default managed engine build uses FFmpeg development libraries, X11/XComposite/XRandR/XFixes/XDamage, Wayland client/EGL and scanner, D-Bus, libdrm, libva, libcap, libpulse, PipeWire and SPA headers. Missing tools or development inputs break configuration, compilation or staging. AppImage users consume the built artifacts. [Linux build](../linux/build.sh), [engine build](../linux/engine/build.sh), [Meson dependencies](../linux/third_party/gpu-screen-recorder/meson.build), [protocol generation](../linux/third_party/gpu-screen-recorder/protocol/meson.build)

## Capture boundary and follow-up findings

The replay-on-launch timer, dashboard and capture command reach `Controller::toggleCapture`. Standalone recording uses the same engine start with different output arguments. Recording during replay sends an IPC request to the running engine. The controller observes input status for the editor and marks sidecar timing, but neither startup path branches on input status or grant results. The composition plugin required by capture is distinct from the input settings panel. [Controller](../linux/app/controller.cpp), [engine](../linux/capture/gsr_capture.cpp)

1. To support portal-only installations without a KMS payload, change the unconditional preflight/staging in `linux/packaging/AppRun` and `linux/engine/launch-recorder`. To avoid a KMS prompt by default, review source ordering in `Settings::capture`. There is no automatic portal retry on KMS denial.
2. To degrade individual editor, microphone and shortcut features when their host tools are missing, narrow the AppImage startup checks. The AppImage builder also explicitly requires the input setup executable at packaging time even though the finished app can run without it. [AppRun](../linux/packaging/AppRun), [bundle staging](../linux/packaging/build_appimage.py)
3. The standalone test checks direct references in the application entry point, controller, recorder adapter, audio startup and launch scripts. Adding it to the aggregate suite requires edits to `linux/Shadowless.pro` and `linux/build.sh`. It does not exercise a running compositor, GPU, authorization dialog or transitive UI behavior. The earlier CachyOS/Hyprland spike used an already configured KMS helper. Portal capture and live Plasma behavior still need desktop validation. [Compatibility test](../linux/tests/compat/tst_capture_independence.cpp), [spike results](LINUX_GSR_SPIKE.md), [Linux runtime notes](../linux/README.md)

Run from the repository root in a separate build directory:

```sh
project_dir=$PWD
build_dir=$(mktemp -d)
cd "$build_dir" && qmake6 "$project_dir/linux/tests/compat/CompatTests.pro" && make && ./shadowless-compat-tests
```
