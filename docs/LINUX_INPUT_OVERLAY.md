# Input overlay (keyboard, mouse, gamepad)

Medal-style overlay showing pressed inputs. Phase 1: a live preview inside **Capture overlays** (the overlay settings, not general Settings), an optional
timestamped sidecar next to each clip, and an editable overlay drawn by the editor over a
clean video. Burning the overlay into captured frames (GSR composition) is out of scope.
Everything is **opt-in and off by default**. The same layout JSON and sidecar format are
used by the Linux and Windows branches; only the input source differs.

## Components (`linux/overlays/input/`)

| Part | Where | Notes |
| --- | --- | --- |
| Contract: `InputId`, `InputEvent`, `InputState`, `InputSource`, `FakeInputSource` | `core/` | Qt-only, no platform code |
| Layouts (JSON) + `Layout` loader/validator, `renderInputOverlay` | `core/` | 5 built-ins in `core/layouts`, regenerated by `generate_layouts.py` |
| `EvdevInputSource` (Linux) | `source/evdev_*` | allowlist-only, hotplug, permission reporting |
| `InputRecorder` (sidecar writer) | `source/input_recorder.*` | depends only on the contract |
| Windows source | later, C# in `windows` | `WH_KEYBOARD_LL` / `WH_MOUSE_LL` + gamepad API, same ids and layouts |

## Ids

Stable strings. Keys are **physical positions** named after the US-QWERTY legend, so QWERTY
and AZERTY layouts share ids and differ only in labels (`key.q` is the key labelled `A` on
AZERTY). Linux maps evdev key codes, Windows maps scan codes (`win`; `0xE000 | code` when extended).

* `key.<name>`: `a`..`z`, `0`..`9`, `f1`..`f12`, `esc tab caps enter space backspace grave minus equal lbracket rbracket backslash semicolon apostrophe comma period slash lshift rshift lctrl rctrl lalt ralt up down left right`
* `mouse.left right middle back forward` (evdev 272-276) and `mouse.wheelup` / `mouse.wheeldown` (momentary: down then up in the same event batch)
* `pad.south east west north l1 r1 l2 r2 l3 r3 select start mode` (evdev `BTN_SOUTH`=304, `EAST`=305, `NORTH`=307, `WEST`=308, `TL`=310, `TR`=311, `TL2`=312, `TR2`=313, `SELECT`=314, `START`=315, `MODE`=316, `THUMBL`=317, `THUMBR`=318) and `pad.dpad.up/down/left/right` (hat `ABS_HAT0X/Y`)
* DualSense (`hid-playstation`, "Wireless Controller") is an ordinary evdev gamepad, so the same codes apply. L2/R2 count as pressed from their digital button (`BTN_TL2`/`BTN_TR2`) or when the analog axis passes 50%. Analog stick direction is not part of v1.

## Layout JSON (schema 1)

`{schema, id, name, scope: gameplay|full|pad, width, height, elements[]}`; each element
`{id?, label, shape: round|circle|mouseBody|mouseLeft|mouseRight|padBody, x, y, w, h, evdev?, win?, vk?, hat?}`
in layout units. Elements without `id` are decoration. `Layout::allowlist()` (the ids of all
interactive elements) is the only set a source may emit.

## Sidecar v1: `<clip>.inputs.json`

```json
{"schema":1,"layout":"qwerty","durationMs":183400,"events":[[1520,"key.w",1],[1730,"key.w",0]]}
```

* `events`: `[t_ms, id, down]`, ordered by `t_ms`, relative to the start of the clip (replay
  buffer clips: relative to the clip's first frame). `down` is `1` or `0`.
* No wall-clock time, device names, text, scan codes or ids outside the layout allowlist.
* `InputRecorder::writeWindow(clip, startMs, endMs)` takes `monotonicMs()` bounds: a replay clip is the buffer window that ended when the save was requested; a recording runs from its first frame to the stop request. Paused recordings are skipped. Enabling saved events mid-capture covers only inputs from that moment.
* Written to `*.tmp` then renamed; at most 200 000 events (excess dropped, `"truncated":true`).
* Missing or invalid sidecar means "no overlay"; the clip is never modified.
* KPS and other statistics are derived from these events later; nothing else is stored.

## Privacy

* Off by default; the sidecar has its own switch. A source only runs while the overlay or
  sidecar is enabled and a layout other than None is selected.
* Gameplay layouts expose a small key set and cannot reproduce typed text. The **Full**
  layout includes every letter, so key timing could be used to reconstruct typing; the UI
  must warn before enabling it and the sidecar for that layout is clearly labelled.
* Nothing is logged, and `statusDetail()` never contains key data.

## Permissions on Linux

**Graphical setup (default).** The Capture overlays page offers **Enable input access…**: you choose the keyboards and mice, the system
asks for authorization once (polkit), and a small helper installs a narrow per-device rule that persists across restarts. Design and
security model: `LINUX_INPUT_ACCESS.md`. Nothing is changed unless you authorize it, and declining leaves Shadowless fully usable.

**Manual setup (fallback, or if you prefer it).** Shadowless itself never modifies permissions without that authorization.

`/dev/input/event*` is normally `root:input`, mode `0660`. Shadowless never modifies
permissions and never asks you to join the `input` group (that grants every program you run
read access to all keyboards). The Capture overlays page explains the problem and shows the steps; the
user runs them. Preferred: a narrow udev rule that tags only the needed device classes for
the active seat session, installed by the user:

```
# /etc/udev/rules.d/70-shadowless-input.rules   (then: sudo udevadm control --reload && sudo udevadm trigger -s input)
SUBSYSTEM=="input", KERNEL=="event*", ENV{ID_INPUT_KEYBOARD}=="1", TAG+="uaccess"
SUBSYSTEM=="input", KERNEL=="event*", ENV{ID_INPUT_MOUSE}=="1", TAG+="uaccess"
SUBSYSTEM=="input", KERNEL=="event*", ENV{ID_INPUT_JOYSTICK}=="1", TAG+="uaccess"
```

Drop the keyboard line to support only mouse and gamepad overlays. The `uaccess` tag grants
the user logged in at the seat, not a group. Unreadable devices are retried with bounded backoff and again when a device node changes or reconnects; opening Capture overlays also triggers one retry.
Without access `InputSource` reports
`PermissionDenied` and the overlay simply shows nothing. Under Wayland there is no other
supported way to read global key state, and compositor shortcuts cannot report arbitrary keys.

Unit tests cover layouts, rendering, the contract and (with fake descriptors) the evdev
reader and recorder. Real keyboards, hotplug on a live desktop and a physical DualSense are
